# 控制方案路线 — 与《飞镖闭环仿真方案讨论》对齐

> 2026-10-21 | 来源: 飞书文档《飞镖闭环仿真方案讨论》(杨铠鸣, 10-19 修改) | 整理: CFD 侧
> 归口: 接口规范仍以 `guidance_loop_dev_spec.md` 为准; 本文记录方案取舍与 CFD 侧影响。

## 1. 文档原方案与补充

**原方案流程**: PSO (粒子群调参) → 监督学习 → RL → 输出一个 RL 训练的神经网络部署实机。

文档补充的四项细节:

1. **电控-视觉接口**: 统一 `BaseGuidance.update(obs) -> [δ1..δ4]`, 两个实现类——
   `ClassicalGuidance(params)`(N / sliding_gain 由外部优化器以字典传入, 拒绝硬编码)、
   `NeuralGuidance(model_path)`(ONNX/TFLite)。仿真器只闭环, 对算法一无所知。
2. **RL 奖励**: ①视线角 `R=1/(|e|+0.1)` ②纵向拉近 D_t<D_{t-1} ③舵角平方和+打舵速率惩罚
   ④**α/β 超 15° 判 -500 并终止** ⑤<0.5m 命中 +1000 / 落地未命中 -1000。
3. **初始状态散布**: 空投"交接班窗口"下不加干预会过拟合单点。
4. **Swarm 抗散布**: ①蒙特卡洛评估(散布 ±2m、初速 15~25 m/s, 每次抽 20 个初态取平均/最差)
   ②网格化专家库(初始散布空间切 1000 点, 每点单独 Swarm → 海量轨迹喂 NN)。

## 2. 文档提出的两个优化方向

| | 优化 A: DAgger (交互式数据聚合) — 强烈推荐 | 优化 B: 残差 RL (Residual RL) — 安全保底 |
|---|---|---|
| 核心 | 传统导引律(电控团队)当专家导师 | NN 只输出对传统算法的**修正量** |
| 流程 | 随机风偏/初位下跑 PN → 收集专家集(SL预训练) → NN 接管试飞 → 出范围立刻呼 PN 修正并入题库 | 最终舵角 = PN 基准 + NN 补偿 |
| 优势 | 绕开 RL reward 调参地狱; 底层监督学习必收敛; 鲁棒性不亚于域随机化 RL | 传统算法保飞行安全, NN 只抵消非线性气动误差与风偏; 训练难度降 80% |

## 3. 我的评估: 两条优化都建在同一块地基上

**结论: 不管选 A 还是 B, 都先要有可用的经典导引律 + 高保真气动环境。**
A 的专家就是传统 PN, B 的基准也是传统 PN —— 所以"经典控制基线"不是备胎, 是两者的前置。
纯 end-to-end RL(原方案末段)反而应当最后做: 文档自己列的奖励项里, 舵角平方和/速率惩罚、
α/β 15° 终止、能量项, 全是我要的物理约束, 而纯 RL 最容易被这些约束"教会作弊"。

推荐顺序:
```
Step 1  经典 PN+PID 参数枚举 → M2/M3 验收   (产出: 可交付电控的参数组 + 专家策略)
Step 2  文档 A: DAgger —— 用 Step 1 的 PN 当专家, 收集(状态, 正确舵角)对训 NN
        文档 B: 残差 RL —— 若 A 的 NN 在风偏下仍不稳, 退化到"PN + NN 补偿"最保险
Step 3  纯 RL / 网格化专家库(1000 点) —— 算力充沛且前两步都做扎实后再考虑
```

## 4. CFD 侧影响: 扫气范围必须按文档的安全阈值扩

文档奖励 ④ 把 **α/β > 15° 判死**, 蒙特卡洛用**初速 15~25 m/s、散布 ±2m**。因此气动表:

| 维 | 原 spec 拟定 | **按文档修正** | 理由 |
|---|---|---|---|
| V | [15, 30] | **[15, 25] 主体 + 30 留余量** | 初速散布 15~25; 末端可能更快 |
| α | [−5°, 15°] | **[−15°, 15°]** | 奖励把 ±15° 当安全边界, 策略会贴着边界飞 |
| β | 待定 | **[−15°, 15°]** | 同上, 风偏对抗会用到 |
| de/da/dr | ±20° | **±20°** (工作区加密) | 舵机行程 |

**这是硬需求**: 表没覆盖到的区域, 仿真里查表会 clamp 到边界 → 策略学到"物理谎言",
上实机必翻车。文档的 15° 终止条件必须与表边界一致。

## 5. 接口兼容性备注

文档接口 `BaseGuidance.update(obs) -> list` 与 spec §4.5 的
`Guidance.update(obs, detection, dt_vis) -> (4,)` **不冲突**: 前者是电控部署口径(obs 已含识别结果),
后者是仿真内口径(视觉链路分离)。落地时在 `NeuralGuidance` 里做一层适配即可;
DAgger 的"专家介入/出范围判定"需要主循环支持切换控制器, 建议在 sim_core 的
`run_episode` 里加 `guidance_switch(module)` 钩子。
