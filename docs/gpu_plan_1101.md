## 1. GPU 该干什么（岗位说明）

OpenFOAM 扫气是 CPU 活，GPU 帮不上 FVM——GPU 的岗位是 **T2 LBM 瞬态线**：
1. **R8b 平行基准瞬态**（v4 真轴几何）：fy 对称性 + 与 FVM 蓝表量级对拍 → 进 v0.96/v1.0 交付物
2. **大攻角端点瞬态统计**（|α|≥12.5°，β± 非对称涡）：FVM 稳态在此最弱（侧向分支不确定 10% 级），
   GPU 瞬态统计是最有价值的补充——正是 CPU 空窗期最该干的活
3. **跨代码对拍**（FVM↔LBM 双代码同工况）→ v1.0 的置信度背书

## Phase 0 执行结果（11-01 当晚 — 计划 → 破案 → 复产 → 批次在跑）

### 体素化玄学破案：两个叠加的 bug

| # | bug | 机制 | 修复 |
|---|---|---|---|
| ① | **`object_force` 精确匹配 `TYPE_S\|TYPE_X`**，而 `voxelize_stl` 只打 TYPE_S → 求和器数到 0 个格 → **力恒等于 0** | 官方 Stokes 示例（setup.cpp L187+）明示固体要"additionally with TYPE_X for force summation" | 体素化后补标 TYPE_X（setup.cpp 一行） |
| ② | **多壳 STL 击穿射线奇偶体素化**：26 件 CONCAT 整文件 / OCC fuse 的重叠壳让 parity 射线大面积误填 → 假固体块 → 假阻力（实测 −1273/−2290 vs 正常 −37，15-60 倍） | 修复①后现形——此前 bug① 把烂力全显示成 0，水面下的雷被完全遮蔽 | **逐零件体素化**（body_01..26.stl 每件单壳循环 + fin 循环） |

证据链：备份二进制 bak_v4 同几何力非零（−84.5 @ step500，管线无罪）→ 四变体矩阵全零（与几何无关）→ 官方示例对读（TYPE_X 口径）→ 修复后 v4parts 力健康、多壳变体爆表（bug② 定量现形）。

### 工程教训

- **两个 bug 叠加时，第一个会把第二个的症状完全遮蔽**（力恒零掩盖了体素化误填）——修复遮挡 bug 后要立刻重新审视此前"正常"的判读
- 观测缺失是玄学的温床：体素计数从未被打印过，Phase 0 的第一产出应该是可观测性
- 备份二进制是最快的对照实验（bak_v4 2 分钟定界"源码坏 vs 几何坏"）
